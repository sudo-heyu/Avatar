# 用户满意度分析 · 安卓端对接说明

本文总结：游客侧 App 在「满意度」链路里**需要做什么**、**已有哪些 HTTP 接口**、**管理端与分析能力与 C 端的分工**。口径以当前仓库后端实现为准（见 `docs/api/API_CONTRACT.md`）。

---

## 一、角色划分

| 端 | 职责 |
|----|------|
| **游客安卓 App（C 端）** | 在用户操作后**上报**满意度/投诉（打分、可选评语）；不负责生成「感受度报告」全文。 |
| **管理 Web / 数据大屏** | 展示聚合统计（均分、正向占比、趋势、热门问等），数据依赖 C 端上报与会话/消息落库。 |
| **后端** | 校验、写入 `visitor_feedback`；管理端 `dashboard/overview`、游客感受度报告等聚合查询。 |

说明：**未调用满意度上报接口时**，管理端「满意度」相关指标会长期为空或极少——与代码注释一致。

---

## 二、安卓端（游客）必做：满意度 / 投诉上报

### 2.1 业务动作（产品侧）

- 单次或多次打分：**1～5 分**（5 为最满意）。
- 可选：**投诉**（`is_complaint: true`）。
- 可选：**文字评论**（≤500 字）。
- 建议：在一次问答结束后展示入口，并与**当前会话 / 当前助手回复**关联，便于排障与归因。

### 2.2 接口（已实现）

| 项目 | 说明 |
|------|------|
| **方法 / 路径** | `POST /api/v1/chat/feedback` |
| **请求体** | 见下表 |
| **成功** | 统一包装 `code === 0`，`data` 含 `feedback_id`、`created_at` 等 |
| **鉴权** | 当前实现未在路由层单独写 Bearer，与现有 chat 一致；若生产环境对会话有校验，需与全链路鉴权方案对齐。 |

**请求字段（与 `ChatFeedbackRequest` 一致）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `scenic_id` | String | 是 | 景区 ID，服务端做 canonical 校验 |
| `rating` | Int | 是 | **1～5** |
| `session_id` | String | 否 | 若传，须为已存在且属于该 `scenic_id` 的会话，否则 **404** |
| `user_id` | String | 否 | 建议传，便于统计维度 |
| `message_id` | String | 否 | 对「本轮助手回复」打分时传该条 `message_id` |
| `is_complaint` | Boolean | 否 | 默认 `false`；`true` 计投诉 |
| `comment` | String | 否 | 最长 500 字 |

**响应 `data` 示例字段**：`feedback_id`、`scenic_id`、`session_id`、`user_id`、`message_id`、`rating`、`is_complaint`、`comment`、`created_at`（与 `VisitorFeedback.to_dict()` 一致）。

**错误码（节选）**

| code | 含义 |
|------|------|
| 1002 | 参数非法（如 `rating` 越界） |
| 404 | 传了 `session_id` 但会话不存在或与景区不匹配 |

### 2.3 与聊天主链路的配合

- 创建会话、发问答仍用既有接口（如 `POST /api/v1/session/create`、`POST /api/v1/chat/text` 或流式 `/chat/text/stream`）。
- **满意度上报独立请求**，可在用户点击「提交评价」后发起；无需塞在 SSE 里。

## 三、管理端 / 分析用接口（一般不在游客 App 内调用）

以下接口用于**运营后台或内部大屏**，普通游客 App **通常不需要**接入；若做「景区管理端 Android」可再评估。

| 接口 | 用途 |
|------|------|
| `GET /api/v1/admin/dashboard/overview?scenic_id=` | 聚合：服务人次、满意度均分/正向占比、投诉相关统计、满意度趋势（近 14 天 UTC）、热门问等。其中满意度统计依赖 **`POST /chat/feedback` 写入的数据**。 |
| `GET /api/v1/admin/reports/visitor-sentiment?scenic_id=` | 「游客感受度报告」草案：返回 `focus_points`（来自热门问）、`emotion_trend`（当前实现可为占位 **`[]`**）、`service_suggestions`（当前为示例模板句）。 |

---

## 四、安卓端当前缺口与可选增强

| 能力 | 现状 | 建议 |
|------|------|------|
| 上报满意度 | 有接口 **`POST /api/v1/chat/feedback`** | 做 UI + 调用 + 失败重试/提示 |
| 查询「我的历史反馈」 | **无游客侧列表接口** | 若产品需要，需新增 `GET`（按 `user_id` 分页）类接口 |
| App 内展示「景区满意度大屏数据」 | 无 C 端专用报表接口 | 可用管理端接口需鉴权，不建议把 admin 接口暴露给游客包；若要给游客看摘要，需单独设计只读、脱敏 API |
| 情感趋势、词云、NLP 报告 | 报告接口中 `emotion_trend` 等可能为空或占位 | 以后端扩展为准；App 仅展示时等新接口约定 |

---

## 五、数据流小结（从点击到管理端大屏）

```text
用户在 App 打分 / 投诉
        ↓
POST /api/v1/chat/feedback
        ↓
visitor_feedback 表落库
        ↓
管理端 GET /admin/dashboard/overview 聚合展示（satisfaction 等）
可选：GET /admin/reports/visitor-sentiment 生成报告型结构
```

**结论（给安卓同学的一句话）**：满意度分析在 C 端的首要工作是 **对接并实现 `POST /api/v1/chat/feedback`**；管理端与大屏上的满意度曲线、均分等**依赖本条数据**。展示类「感受度报告」详情页在游客 App 侧暂无专用只读接口，需与管理端产品线区分或后续补 API。
