# 数字人 Combo 设计文档

## 1. Combo 概念

**Combo** 是数字人的最短情感表现单元，将表情、动作、短语音打包为一个独立的情感片段。

- **时长**：1～3 秒
- **组成**：expressionTimeline + motionQueue + 可选短 TTS（≤4 字感叹词）
- **粒度**：一个情感状态，可单表情+单动作，也可表情渐变+动作序列
- **定位**：衔接/过渡/氛围，不承载实质性信息内容
- **TTS**：仅感叹词（"嘻嘻"、"哇"、"嗯…"），用于驱动唇形和增强感染力，不描述实物

### 1.1 与 Scenario 的区分

| 维度 | Combo | Scenario |
|------|-------|----------|
| 时长 | 1～3s | 10～15s |
| TTS 文本 | ≤4 字感叹词 | 完整讲解段落 |
| 信息量 | 零（纯情感） | 实质性内容 |
| 用途 | 大模型按情绪选配 | 固定场景讲解 |
| 触发 | LLM 自动匹配 | 用户点击/系统触发 |

## 2. 设计目标

Combo 是大模型的**"情感表情动作库"**。大模型根据用户输入的词语/短语的情感色彩，从 Combo 库中选择最匹配的一个，插在 TTS 播报之前、之后或独立播放。

```
用户说"太美了！"
  → LLM 判定情感: [喜悦, 赞叹]
  → 匹配 Combo: "开心地笑" (tags: 开心, 哈哈, 嘻嘻, 太美了)
  → 播放 Combo（1.5s）→ 可接正式 TTS 讲解
```

## 3. 设计流程（强制）

每个 Combo 必须按以下步骤设计，不可跳过任何一步：

### Step 1: 明确情感目标
- 确定情感维度（喜悦/关切/敬畏/歉意/惊喜/思考）
- 确定使用场景（过渡/回应/氛围）
- 写出目标用户输入示例（3～5 个短语）

### Step 2: 查阅表情参数
- 读取候选表情的 `.exp3.json` 文件
- 逐个参数对照视觉目标，确认能否实现
- 记录关键参数值作为设计依据

### Step 3: 编排时间轴
- expressionTimeline：表情切换时机与渐变
- motionQueue：动作起始偏移与持续时长
- TTS 文本：感叹词选择与音节节奏
- 确保三者节奏对齐

### Step 4: 设计 emotionTags
- 覆盖目标输入的直接表达和同义变体
- 口语化（"太美了"）与书面化（"赞叹"）并重
- 5～15 个，与同类 Combo 有清晰边界

### Step 5: 自检清单
- [ ] 表情参数能支撑目标视觉效果
- [ ] 动作起始偏移与 TTS 音节节奏对应
- [ ] emotionTags 覆盖目标输入示例
- [ ] 与其他 Combo 在情感色彩上可区分
- [ ] 时长 ≤ 3 秒

## 4. 情感分类体系

| 情感维度 | 典型输入 | Combo 视觉特征 | 适用场景 |
|---------|---------|---------------|---------|
| **喜悦 Joy** | 太美了、真好、哈哈 | 半眯眼、笑眼弯弯、嘴角上扬 | 用户表达满意/赞美/开心 |
| **关切 Care** | 注意、小心、当心 | 眉头上扬(八字眉)、嘴微抿 | 安全提醒、温和警告 |
| **敬畏 Awe** | 好庄严、太震撼 | 眼睁大、微微仰头、嘴微张 | 宗教文化场景、宏伟景观 |
| **歉意 Sorry** | 抱歉、不好意思 | 眉头微蹙、视线下垂、欠身 | 兜底回复、无法满足需求 |
| **惊喜 Surprise** | 哇、天哪、真的吗 | 眼睁大、眉毛上挑、嘴张开 | 用户表达惊讶 |
| **思考 Thinking** | 嗯…、让我想想 | 侧目、单手托腮状、嘴微抿 | LLM 推理中、等待查询 |
| **鼓励 Encourage** | 加油、没问题 | 点头、坚定眼神、微笑 | 用户犹豫、需要肯定 |

## 5. 数据结构

### 5.1 ComboButton

```kotlin
data class ComboButton(
    val id: String,                // "happy_giggle"
    val label: String,             // "开心地笑"
    val emotionCategory: String,   // "喜悦"
    val emotionTags: List<String>, // ["哈哈", "嘻嘻", "开心", "太美了", ...]
    val description: String,       // 人类可读描述
    val action: AvatarPlayAction   // 编排好的播放动作（含短 TTS）
)
```

### 5.2 emotionTags 设计原则

- 包含**目标输入短语本身**和**同义表达**
- 口语化与书面化并重
- 每个 Combo 5～15 个 tags
- 同一情感维度的 Combo 之间 tags 允许部分交叉，但核心区分词不可重叠

## 6. 已实现 Combo

### C1: 开心地笑 `happy_giggle`

- **情感维度**：喜悦 Joy
- **用途**：与游客开心互动、回应赞美、活跃气氛的过渡表现，**不用于描述实质性内容**
- **时长**：约 1.5 秒

#### 表情参数依据

基于 `happy.exp3.json` 实测参数：

| 参数 | 值 | 视觉效果 |
|------|-----|---------|
| `ParamEyeLOpen` | 0.1 (Add) | 双眼只睁开 10%，**半眯眼** |
| `ParamEyeROpen` | 0.1 (Add) | 同上，对称眯眼 |
| `ParamEyeLSmile` | 1.5 (Add) | 笑眼弯弯弧度 |
| `ParamEyeRSmile` | 1.5 (Add) | 同上 |
| `ParamMouthForm` | 1.0 (Add) | 嘴角上扬微笑 |
| `ParamMouthOpenY` | 0.3 (Add) | 嘴微张，为 TTS 唇形留叠加空间 |
| `ParamCheek` | 1.2 (Add) | 脸颊上提，笑意饱满 |
| `ParamBrowLY/RY` | 1.0 (Add) | 双眉上扬，开心神态 |

**结论**：HAPPY 表情天然实现"半眯眼微笑"，无需额外定制。

#### TTS 设计

- **文本**："嘻嘻"
- **音节**：xī xī（两个清辅音+高元音，口型小而紧）
- **唇形效果**：TTS 驱动 ParamMouthOpenY 在基础值 0.3 上叠加波动，形成"张嘴-合嘴-张嘴-合嘴"的节奏，即"嘻嘻地笑"
- **为什么不用"哈哈"**："哈 hā"元音开口度大，"嘻 xī"口型紧小，配合 HAPPY 的 MouthForm=1.0（微笑嘴型），"嘻嘻"更贴近自然偷笑/轻笑

#### 动作编排

- **NOD × 2**，分别对齐两个"嘻"音节：
  - 0ms: NOD (400ms) — 第一个"嘻"，头微点
  - 450ms: NOD (400ms) — 第二个"嘻"，头再点
- 两个点头形成笑的节奏感

#### 表情时间轴

| 时间 | 表情 | 强度 | 说明 |
|------|------|------|------|
| 0ms | HAPPY | 0.82f | 眯眼笑起始 |
| 700ms | HAPPY | 0.86f | 笑意加深（眼更眯） |

#### 情绪标签

`哈哈, 嘻嘻, 开心, 笑, 好笑, 有趣, 欢乐, 太美了, 真好, 真棒, 好漂亮, 哈哈哈哈`

#### 大模型匹配逻辑

LLM 在以下情况选择此 Combo：
- 用户输入含直接笑声词（哈哈/嘻嘻/嘿嘿）
- 用户表达正面情绪（太美了/真好/真棒/好漂亮）
- 作为正面回答前的暖场过渡（"哈哈，让我来告诉你…"）
