# 数智寻踪——红色景区AI数字导览系统

## 一、项目背景

### 1.1 红色旅游数字化转型的迫切需求

红色旅游是传承革命精神、弘扬爱国主义教育的重要载体。据统计，全国红色旅游景区年接待游客量超过15亿人次，但传统导览模式面临三大痛点：

- **讲解服务供给不足**：热门景区节假日讲解员供不应求，自助导览设备内容固化、交互性差
- **年轻群体参与度低**：传统展陈方式对Z世代吸引力不足，缺乏沉浸式、互动式体验
- **知识获取碎片化**：游客对红色历史背景了解有限，难以建立系统性认知，现场疑问无法即时得到深度解答

### 1.2 AI技术赋能红色文化传播的历史机遇

随着大语言模型（LLM）、实时语音合成（TTS）、计算机视觉和数字人技术的成熟，AI已具备构建"24小时在线、千人千面、深度互动"的智能导览能力。将AI数字人技术与红色景区知识库结合，能够实现：

- 革命历史知识的**即时问答与深度解读**
- 多模态交互（文本/语音/图文）的**无障碍体验**
- 情感化、人格化的**数字人播报讲解**

### 1.3 项目定位

**数智寻踪**是一款面向红色旅游景区的Android端AI数字导览应用。项目以"让红色历史活起来，让革命精神传下去"为核心理念，通过大模型驱动的智能问答、Live2D数字人实时播报、端侧语音识别等前沿技术，为游客提供沉浸式的红色文化学习体验。

## 二、主要研究内容

### 2.1 系统架构

项目采用**MVVM + Repository**分层架构，结合Jetpack Compose声明式UI，确保代码的可维护性与可测试性。

```
┌─────────────────────────────────────────────────────────────┐
│                        UI 层 (Jetpack Compose)               │
│   ┌─────────────┐ ┌─────────────┐ ┌─────────────────────┐    │
│   │  MainScreen │ │ ScenicIntro │ │   SettingsScreen    │    │
│   │  (对话核心)  │ │  (景区导览)  │ │    (系统设置)       │    │
│   └─────────────┘ └─────────────┘ └─────────────────────┘    │
├─────────────────────────────────────────────────────────────┤
│                      ViewModel 层                            │
│         MainViewModel / ScenicIntroViewModel                  │
├─────────────────────────────────────────────────────────────┤
│                     Repository 层                            │
│   GuideRepository │ SessionRepository │ ScenicIntroRepo     │
├─────────────────────────────────────────────────────────────┤
│                      Data 层                                 │
│   Remote (Retrofit+OkHttp/SSE) │ Local (DataStore)           │
├─────────────────────────────────────────────────────────────┤
│                      Core 层                                 │
│   Avatar(Live2D) │ TTS(Edge-TTS) │ ASR(讯飞) │ Audio(Exo)  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 核心功能模块

#### 2.2.1 流式智能问答系统

- **SSE流式响应**：基于OkHttp直连Server-Sent Events，实现`text_delta`增量展示，首字延迟<1.5s
- **TTS分段同步播放**：后端返回`tts_segment_ready`事件携带音频URL与词级时间标记(marks)，前端按序排队播放，实现"边说边听"的自然体验
- **打字机音画同步**：文字展示与TTS播放精确同步，首个音频片段就绪后才启动文字逐字显示，1.5秒超时兜底
- **自动续写机制**：流式响应异常中断时，基于已生成文本自动构造续写提示词，最多续写3次，弱网下80%以上中断可恢复

#### 2.2.2 Live2D数字人播报系统

- **实时渲染引擎**：基于Live2D Cubism 4 Native SDK，通过JNI桥接实现Android端高性能渲染
- **15种高精度Viseme口型**：针对中文语音特点，构建覆盖双唇音、舌尖音、舌根音、开口呼、齐齿呼等完整口型体系，实现精准的唇形同步
- **13种表情状态**：neutral、happy、thinking、excited、concerned、apologetic、welcoming、approving、playful、reverent、surprised、grateful、focused，根据对话情感动态切换
- **14种上身动作**：nod、wave、point_left/right、guide、listen等，结合景区讲解场景语义化触发
- **动作优先级系统**：支持HIGH/NORMAL/LOW三级优先级，高优先级动作可打断低优先级，保证关键表达不被中断

#### 2.2.3 端侧语音识别

- **讯飞SparkChain SDK**：端侧ASR本地识别，无需网络依赖，保护用户隐私
- **长按交互**：长按语音按钮触发录音，上滑取消，松开自动识别并填入输入框
- **实时音量反馈**：录音过程中实时显示音量波形，提供触觉反馈

#### 2.2.4 红色景区知识导览

  1. 辛亥革命纪念馆
  2. 八七会议会址纪念馆
  3. 向警予烈士陵园
  4. 施洋烈士陵园
  5. 武汉二七纪念馆
  6. 武汉中共中央机关旧址纪念馆
  7. 武汉抗战纪念园
  8. 八路军武汉办事处旧址
  9. 汉口新四军军部旧址
  10. 毛泽东故居陈列馆
  11. 京汉铁路总工会旧址
  12. 汉口中华全国总工会旧址
  13. 中共中央领导人汉口住地旧址
  14. 起义门
  15. 中山舰博物馆
  16. 贺胜桥北伐阵亡将士陵园

- **沉浸式绘本式导览**：针对重点景区（辛亥革命纪念馆、八七会议会址纪念馆）设计七幕沉浸式绘本浏览，包含主题详解、历史故事、人物群像、历史意义等维度
- **多布局内容渲染**：支持TEXT_ONLY、IMAGE_FULL、TEXT_IMAGE_RIGHT、TIMELINE、HIGHLIGHTS、STATISTICS等9种内容布局

#### 2.2.5 会话管理与用户系统

- **会话生命周期管理**：支持会话创建、历史恢复、归档、删除，消息上限100条防OOM
- **用户认证体系**：注册/登录/登出，未登录用户自动生成guest ID，认证状态持久化
- **满意度反馈**：长按助手消息触发评分（1-5星），低分可标记投诉并填写留言
- **多景区切换**：TopAppBar集成景区选择器，支持动态切换当前讲解景区与景点

#### 2.2.6 路线规划（扩展中）

- 支持基于游客偏好（时长、兴趣标签）的智能路线推荐
- 返回结构化路线数据：景点节点、预计停留时间、导航 polyline

### 2.3 后端接口契约

采用统一响应格式 `{code, message, data}`，主要接口：

| 接口 | 说明 |
|------|------|
| `POST /api/v1/chat/text/stream` | 流式问答（SSE主链路） |

| `GET /api/v1/session/list` | 会话列表 |

| `POST /api/v1/upload/image` | 图片上传（图文问答） |
| `GET/POST /api/v1/route/recommend` | 路线推荐 |

## 三、创新点

### 3.1 技术创新

#### （1）流式TTS与数字人口型同步架构

业界首创"流式文本生成 → 分段TTS合成 → 词级marks驱动口型"的三级流水线架构：

- 后端LLM生成文本的同时，边合成TTS音频边输出`marks`（每个词的起止时间+音素）
- 前端按`segment_index`顺序排队播放，不等待全部内容生成，首段音频延迟<2.5秒
- 数字人口型严格依据`marks`中的音素时间轴驱动，实现真正的"字正腔圆"同步效果
- 解决传统方案"先全量合成再播放"导致的5-10秒冷启动问题

#### （2）中文专用高精度Viseme口型系统

针对中文发音特点，构建15种Viseme口型（远超英文5-8种的常规方案）：

- 区分双唇音(b/p/m)、舌尖音(d/t/n/l)、舌根音(g/k/h)
- 区分开口呼(a)、齐齿呼(i)、合口呼(u)、撮口呼(ü)
- 区分擦音(z/c/s vs zh/ch/sh/r)的细微口型差异
- 引入"复合元音过渡"(ua/uai/iao)专用口型，避免元音切换时的生硬跳变

#### （3）端侧ASR + 云端LLM + 流式TTS的端到端低延迟链路

- 语音识别在端侧完成（讯飞SparkChain，延迟<500ms）
- 文本通过SSE流式传输，边生成边展示
- TTS分段就绪即播，无需等待全量音频
- 全链路端到端延迟控制在3秒以内，远超传统"录制→上传→等待→下载→播放"的10秒以上延迟

### 3.2 产品创新

#### （1）红色景区专属知识增强

- 构建16个红色景区的专属知识库，非通用旅游问答
- 针对革命历史场景设计专属数字人动作：参观烈士陵园的"庄重点头"、讲解战役时的"手势引导"、追忆先烈时的"低头致敬"
- 情感映射系统理解"悲壮""敬仰""缅怀"等红色场景特有情绪，触发reverent（庄重）、grateful（感恩）等专属表情

#### （2）沉浸式绘本式景区导览

突破传统"列表+图文"的枯燥展陈方式：

- 为辛亥革命纪念馆、八七会议会址纪念馆设计七幕沉浸式浏览（开篇 → 历史现场 → 核心记忆 → 人物群像 → 历史意义 → 延伸阅读）
- 每幕采用"焦点叙事+主题详解"双层结构，外层提供情感共鸣，内层提供知识深度
- 全用户视角叙事（"你将看到什么""你可以这样理解"），彻底消除开发者/文档视角的疏离感

#### （3）无感会话管理

- 自动判断"首次进入/切换会话/新建对话"三种场景，智能决策是否创建新会话
- 会话ID持久化到DataStore，应用重启后自动恢复上次对话上下文
- 空会话自动丢弃，避免侧边栏积累"新对话"等无效历史记录

### 3.3 工程创新

#### （1）高健壮性流式消费

- 完整处理9种SSE事件类型：MessageStart/TextDelta/TtsSegment/TtsSegmentReady/TtsAudioError/AvatarAction/Sources/Images/Metadata/Done/Aborted/Error/PrematurelyEnded
- 流异常时自动续写（最多3次），基于已生成文本构造"从中断处继续"的提示词
- XML/结构标签正则过滤，防止打字机效果中途闪现半截标签

#### （2）状态机驱动的数字人播放管理

使用密封类`PlaybackState`（Idle/Receiving/Draining）替代多布尔标志，配合`sessionEpoch`计数器，精确处理：
- 跨会话事件丢弃（上轮未消费事件不干扰新会话）
- 播放队列自然耗尽（不强制截断正在播放的音频）
- 主线程契约（所有公开方法主线程调用，避免ExoPlayer并发问题）

## 四、应用场景与价值

### 4.1 典型场景

1. **入园前规划**："我只有两小时，怎么逛辛亥革命纪念馆最值？"→ AI生成个性化路线
2. **现场深度问**："这个展柜里的手稿是谁写的？当时什么背景？"→ RAG检索知识库即时解答
3. **缅怀时刻**：参观烈士陵园时语音询问"这位烈士牺牲时多大？"→ 数字人以庄重表情低声讲述
4. **多轮追问**：从"八七会议是什么"到"会议具体讨论了哪些文件"到"这些文件后来怎么执行的"→ 上下文保持，连续深入

### 4.2 社会价值

- **降低红色文化传播门槛**：AI导览替代传统人工讲解，解决讲解员数量不足问题
- **提升年轻群体参与度**：数字人交互、语音问答符合Z世代使用习惯
- **促进历史知识系统化**：游客可无限追问，建立从"知道事件"到"理解脉络"的深度认知
- **助力景区智慧化升级**：为红色景区提供低成本的数字化导览解决方案
